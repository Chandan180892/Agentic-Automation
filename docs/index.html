Jira in.

Gantry reads your Jira stories, walks each one through six sub-agents, and proposes Xray test cases and a Bitbucket branch. Nothing is written to your systems until you approve it.

How a story becomes a suite
Pull the story from Jira
acceptance criteria, points, labels — criteria parsed even when there is no field for them
Six sub-agents, in order
analyze, clarify, resolve assets, author, verify, review
It revises its own work
when the verifier objects, the author fixes it and the verifier re-checks
You approve, then it publishes
Xray test cases and a Bitbucket PR — never before you say so

Workspace

Your first sign-in creates a workspace. Point it at a Jira project, an Xray project and a Bitbucket repo — the agents pick up from there.

Sessions are httpOnly cookies signed by Auth.js. Gantry never stores a password, and never asks for one.

Each committed story walks the same chain. Nothing reaches Xray or Bitbucket until you approve it on the Results screen.

Top-level agents

Each has one job, a typed input, and a typed output, produced through a forced tool call so a malformed result never reaches your database. qe-pipeline is itself an orchestrator: it runs the six sub-agents below.
